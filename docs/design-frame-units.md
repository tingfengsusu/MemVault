# 视频结构单元抽帧 — 设计稿

> 用途:把「全片均匀抽 max_frames 帧 + 每帧全幅 OCR」换成「先给视频做画像 → 按通道选策略 →
> 以**动作事件/成品展示**为单元落库」,解决 `docs/抽帧问题总结.md` 的 P1~P5,并为
> `docs/design-shopping-review.md` 的片段定位与证据时间轴提供粒度支撑。
>
> 状态:**设计,未实现**。文中每条数字都标注了来源:【实测】= 本机跑过、可复现;
> 【设计】= 尚未实现;【假设】= 有证据但未全量核对。
>
> 实测环境:两条 480×852 竖屏 B站视频 —— #14《12个脑洞大开的冰淇淋指南》(391s,下载于 BV1RSRKByEt2)
> 与《美国政府破天荒入股民企》(458s, BV1UMG86aEuL)。CPU only,无 GPU。
> 测速脚本位于 Video2Shop 仓库 `temp/bench_*.py`(探针/成本/ROI/OCR/弹幕各一份)。

---

## 0. 一句话方案

每个视频先花 **~14 秒**做一次「视频画像」(像素扫描 + 少量 OCR + 人声占比),用画像决定走哪条
通道;再以**动作事件**为切分骨架、以**成品展示镜头**为步骤收尾锚点,产出**单元**:
每单元 = 起始帧 + 结束帧 + 该区间的字幕文本 + 该区间的语音文本,共享 `start_ts`/`end_ts`。
购物稿的 `clips` 与卖点证据直接消费这些单元。

## 1. 现状与实测证据

### 1.1 现状的几个硬数字

| 项 | 实测值 | 说明 |
|---|---|---|
| #14 全片字幕条数 | **221 条**(1Hz 采样的下限),≈1 条/秒 | 逐秒 OCR 全片,去重后统计 |
| 现状 9.6s 均匀抽帧的字幕覆盖 | **15%**(max_frames=40,8/55)~18%(10/55) | 60~120s 窗口 1Hz 地面真值 |
| 现状 max_frames=20 的时长覆盖 | **0~42s / 391s = 11%** | 扫到上限即停(文献已记录,本次复现) |
| 全幅 OCR 的水印命中率 | **52/61 帧 = 85%** | 水印「胡仔一人食 / bilibili」在画面右上 |
| 字幕带 OCR 的水印命中率 | **0/61 = 0%** | 同一批帧,只裁字幕带 |

### 1.2 成本基线(391s 视频)

| 方案 | 耗时 | 倍速 |
|---|---|---|
| 逐点 `set(CAP_PROP_POS_FRAMES)` + 2Hz 取样(现状) | 17.1s | 23x |
| 顺序 `grab()` + 5Hz 取样 | **3.7~4.0s** | ~100x |
| 顺序 `grab()` + 10Hz 取样 | **15s** | 26x |
| 帧签名计算(纯 CPU,不含解码) | 480p 3.0ms/帧、1080p 9.5ms/帧 | 可忽略 |
| ffmpeg `-skip_frame nokey`(只解 I 帧) | 0.5s / 79 帧 | 极便宜的粗筛 |
| ROI OCR(字幕带 480×94) | **~1.0s/帧**(区间 0.19~1.3,波动大) | 全幅 ~1.7s/帧 |

结论:**瓶颈是解码与 OCR,不是采样密度**;顺序解码比逐点 seek 快 7 倍,是最大的一处免费收益。

### 1.3 ROI 判据(修正后的版本)

用「带内文字出现率」×「带内像素变化强度」两项交叉:

| 视频 | y 带 | 文字帧占比 | 变化强度 | 判定 |
|---|---|---|---|---|
| #14 | 0~4% | 90% | 4.43% | 水印/台标(像素不变)→ 排除 |
| #14 | **50~54%** | 80% | **37.50%** | ★ 字幕带 |
| 美国政府 | 79~83% | 40% | 0.78% | 静态水印 → 排除 |
| 美国政府 | **71~75%** | 40% | 7.03% | ★ 字幕带 |
| 美国政府 | 46~50% | 40% | 8.59% | ★ 图表带(附加候选) |

判定规则:【实测】**含文字的带里,变化强度 ≥ 最低者 ×3 的判为活跃文字带**。两片的分离度分别是
8.5× 与 9×。

**「变化强度」的口径(实现时必须照做)**:该带签名(192×16)帧间"变化像素比例"时间序列的
**中位数(P50)**。上表数字就是这个口径 —— 用别的分位数会导致判据整体失效,见坑④。

> 踩过的坑(务必不要再犯):
> ① 按「文字框数量最多」选带 → 选中水印带(10 帧全中),且指标显示 SNR=550562,是**静默失败**;
> ② 按「OCR 文本是否变化」选带 → 水印 OCR 文本本身不稳(`胡仔一人食`/`bibll`/`胡仔`),照样被骗;
> ③ 用「变化强度 ≥ 全带 P75」当门槛 → 在低运动视频上把字幕带挤掉,误判「无字幕带」。
> ④ 【2026-09-20 实现时新踩,同一族】把**每条带自己的强度值**取成 **P75** 而不是 P50 →
>    #14 上水印带算出 **40.4%**(该带内除静止水印外全是运动背景,高分位被背景抬起来),
>    字幕带 61.6%,两条带只差 1.5×,**×3 分离度门槛无人能过**,探针静默返回「判不出来」。
>    换 P50 后:水印带 **5.6%**、字幕带 **38.5%**,分离度 6.8× —— 与上表的 4.43%/37.50% 对得上。
>    要点:**"最大值/高分位"量的是背景运动,"中位数"量的才是那条带自己稳不稳**;③ 和 ④ 是两个坑
>    (③ 是门槛的分位数,④ 是强度值本身的分位数),别只改一个。

### 1.4 分辨率与画质：几乎不影响

| 档位 | 噪声底(P20) | 信号(P90) | SNR |
|---|---|---|---|
| 480p 原生(657kb/s) | 0.17% | 56.7% | 332 |
| 320p | 0.15% | 56.8% | 388 |
| 240p | 0.15% | 56.6% | 386 |
| 480p 重编码 250kb/s | 0.20% | 54.8% | 281 |
| **全帧 32×32(不裁 ROI)** | **3.61%** | 49.0% | **13.5** |

结论:降到 240p、砍到 250kb/s 都不影响;不裁 ROI 才是灾难(噪声底 ×21)。**1080p 唯一代价是解码
量(像素数 ×5)**,检测质量不因此提升 —— 未登录 B站只发 480p,够用。

### 1.5 单元规模(按「动作事件」切分)

| 指标 | 实测 |
|---|---|
| 动作事件数 | **76 个** / 391s |
| 事件时长 | 中位 **2.30s**(P25 0.6s、P75 5.25s) |
| 落盘帧数 | 起止各 1 帧 = **152 帧** |
| 每事件含字幕 | 平均 **2~3 条**(221 条字幕 ÷ 76 事件) |
| OCR 成本 | 152 × ~1.0s ≈ **2.5 分钟** |

### 1.6 成品展示镜头 = 步骤收尾锚点

全帧「静止段 ≥1.0s」全片仅 **7 段**,抽查 2 段核对确认都是成品展示镜头
(80.5s「质地非常绵密」、270.7s「葡萄干吸满了酒味」);放宽到「静息×1.2 + 最短 0.8s」得 **17 段**,
与「12 个配方」的结构量级吻合【假设,未全量核对】。
注意:展示镜头里手仍在动,**是相对静止,必须用本片静息水平的倍数判定,不能用绝对阈值**。

### 1.7 弹幕:可用于广告段标注

| 项 | 实测 |
|---|---|
| #14 弹幕总数 | 675 条(571 滚动 + 104 顶部固定) |
| 含广告类词(接广/金主/甲方/催更/赞助) | **12 条** |
| 其中落在广告段 170~195s | **10 条**(170~180s 3 条、180~190s 7 条) |
| 误报 | 2 条,集中在 330~340s(观众拿代言梗开玩笑) |

结论:词表要含观众黑话;**门槛用「同一时间窗内 ≥2 条」**,可把误报滤掉。
「空降 XX:XX」这类坐标类弹幕在这条视频里为 **0 条** —— 只能当机会信号,不能当依赖。

### 1.8 顺带白拿的元数据

`api.bilibili.com/x/player/v2?bvid=&cid=`(**无需登录**,code=0)返回:
`view_points[]`(章节:from/to/content)、`bgm_info`、`asr_language`。
实测两条测试视频的 `view_points` 均为 **0**(UP 未标章节)、分P 均为 1

## 2. 设计

### 2.1 探针:视频画像(~14 秒)

一次拿全三份证据:

1. **像素证据**(3.7~4s @5Hz、15s @10Hz):顺序 `grab()` 解码,整幅缩到 96×96,算 24 条横带
   各自的「变化像素比例」时间序列。**禁止逐点 seek**。
2. **文字证据**(10~16s):抽 10 帧做带文字框的 OCR,只取「哪条带上有字、出现率多少」——
   **不比较文字内容**(水印 OCR 文本不稳定,比内容会被骗)。
3. **人声证据**:复用现有 `should_ocr` 的 `speech_seconds / duration`。

画像产出:`{字幕带位置(主/备)或「无」, 字幕换行频率, 动作事件频率与时长分布, 人声占比, 异常段}`。

### 2.2 判据

- 活跃文字带 = 含文字带中变化强度 ≥ 最低者 ×3(§1.3)
- 候选位置集:**四角 + 四边中点 + 中部横带 + 全幅兜底**
  (#14 字幕在画面正中 y≈50%,只按四角/四边会漏)
- 允许**多个**活跃带同时入选(字幕带 + 图表带)
- 水印/台标 = 有文字但像素几乎不变 → 排除

### 2.3 通道选择

| 画像 | 策略 |
|---|---|
| 人声占比高、无字幕带 | 语音为主,按变化事件取图示/图表帧 |
| 人声占比低、有字幕带 | 字幕为主,按动作事件取帧 |
| 两者都有 | 双通道,按时间配对 |
| 两者都低(纯动作/音乐) | 只按动作事件取帧 |

品类标签(匹配系统已有分类:`up_categories` + `route_item`)只用于选**先验**,探针事实优先。

### 2.4 单元:动作事件 + 成品展示

- **动作事件**:带内变化强度出现上升沿 → 动作开始;连续 ≥0.4s 回落到静息水平 → 动作结束
- **步骤收尾**:事件结束后的静止段(§1.6)作为成品展示帧
- 每单元落盘 **2 帧**:动作结束帧 + 成品展示帧(即用户定义的「相近两帧 = 动作起始/结束」)
- 每单元附文本:**该区间内的字幕**(2~3 条)+ **该区间内的语音**(用 ASR **原始句子级** `segments`
  求交集,**不能用合并后的 40 秒段**)
- 每单元共享 `start_ts`/`end_ts`;图像与文字**同块落库**(表已支持:`chunks` 有 `media_path`)

### 2.5 双 OCR 通道(与购物稿的硬约束)

| 通道 | 输入 | 频率 | 用途 |
|---|---|---|---|
| 字幕通道 | **字幕带 ROI** | 每个单元(全量) | 步骤配对、广告词过滤(水印 85%→0%) |
| 全幅通道 | **整帧** | 低频(如每 5 帧 1 次) | **卖点/参数浮层文字**(购物稿 §3.2 依赖) |

原因:字幕带裁切会丢掉贴在画面任意位置的规格浮层(购物稿例子:`防水 10000mm`),
所以不能只留字幕通道。成本:152 帧 ROI ≈2.5 分钟 + 30 次全幅 ≈40 秒。

### 2.6 缓存与校验

- 按 UP 缓存画像(字幕带位置、通道、帧密度系数),复用购物稿的 `prompt_bindings`
  表,新增 `stage='frames'`(**不要另建规则表**)
- 每个视频的探针输出用于**校验**是否仍符合该 UP 的缓存:band 位置差 <5% 画面高、
  字幕频率同量级、人声占比同档;超出 → 判「不符合该 UP 常规形态」,单独走全自动并提示用户
- 一条视频内 ROI 可能变(#14 正片字幕 y≈50% → 广告段字幕 y≈84~87%,片尾回到 50%),
  故缓存「主 ROI + 备 ROI」,抽取时逐段验证
- 异常段:只标时间段,不做语义处理

### 2.7 弹幕预处理

抓 `<cid>.xml`(注意:`Content-Encoding: deflate` 是**裸 deflate**,需 `zlib.decompress(body, -15)`),
按词表(接广/金主/甲方/催更/赞助/恰饭/广子…)命中后**按时间窗投票**(≥2 条/窗),
输出广告时间段。作为预处理结果写入条目(只标时间段)。

### 2.8 顺带入库的元数据

`bgm_info`、`asr_language` 写入 `attrs_json`;`rights.is_cooperation` 存为**弱信号**
(#14 为 0 但视频确有广告,不可当判据)。

## 3. 与 shopping-review 的接口约定(5 条,两边共同遵守)

1. **OCR 双通道**(§2.5)——字幕带用于配对,全幅低频用于卖点参数,缺一不可
2. **规则表只有一张**——`prompt_bindings` 加 `stage='frames'`,不新建表
3. **多模态时间轴用结构化单元列表**,不拼纯文本;模型输出**引用单元 id**,
   证据校验从「ts ±2s」升级为「**引用的 id 必须存在**」
4. **`clips` 边界吸附到单元边界**——结构单元当骨架,LLM 只打 `kind`/`reason`
5. **成本门控共用一条规则**——命中规则的视频才加密抽帧,未命中的保持现状(零回归)

## 5. 成本与风险

| 项 | 评估 |
|---|---|
| 单视频新增成本 | 探针 ~14s + 152 帧 ROI OCR ~2.5 分钟 + 30 次全幅 OCR ~40s ≈ **3.5 分钟/条** |
| 何时启用 | 只对命中规则的视频(**字幕为主 / 购物向**)启用;其余保持今天 40 帧零改动 |
| OCR 耗时波动 | 同一台机器实测单帧 0.19~1.7s 不等(与帧内文字框数、CPU 状态有关),**排期按 ~1.0s/帧 估** |
| 长视频 | 探针成本随时长线性(10Hz 全片 26x 实时);OCR 成本随单元数线性 —— 需要 `frames.max_units` 上限 |
| 静默失败 | ROI 选错不会报错、指标反而更好看(§1.3 坑①)。**必须加「判不出来」的合法输出 + 校验步骤** |
| 未验证项 | 成品展示检测只抽查 2 帧;动作事件阈值与「字幕带/动作带分开取」未做消融 |

## 6. 验收标准(若实施)

- [ ] #14 的单元数在 70~90 之间,事件中位时长 2~3s;落盘帧数 ≈ 单元数 ×2
- [ ] 字幕条覆盖从现状 15% 提升到 ≥90%(以 1Hz 逐秒 OCR 的字幕清单为基准)
- [ ] 全幅 OCR 的水印命中率 <5%;卖点/参数类文字(含数字的行)仍存在于全幅通道产物中
- [ ] 检索「转转」命中的广告块**带广告时间段标记**(或按标记可过滤)
- [ ] 未命中规则的视频:帧数、块结构、`content_text` 与今天**完全一致**(pytest 全绿,零回归)
- [ ] 任一探针输出异常(如画找不到字幕带)时,管线退回现状策略并且**日志可见**「已回退」

## 7. 诚实边界

**已实测可复现**:顺序解码 vs seek 的 7 倍差、ROI 判据的 ×3 规则与两片分离度、
水印命中 85%→0%、字幕 221 条/1 秒节奏、均匀抽帧 15% 覆盖、动作事件 76 个、
全帧静止段 7 段与成品展示抽查、弹幕广告词命中与时间窗、`player/v2` 章节接口与空结果、
分辨率/码率不敏感(240p SNR 386)。

**只是设计**:探针模块、双 OCR 通道、单元化落库、UP 缓存与校验、弹幕投票门槛、clips 吸附。

**有证据但未全量核对**:成品展示 = 步骤收尾(仅核对 2 帧、量级与「12 个配方」吻合);
动作事件与「配方步骤」的一一对应关系。
